SAP CPI Adapters Overview
Source: SAP Help Portal - Connectivity Adapters

Adapters in SAP CPI are components that enable communication between the integration platform and external systems. Each adapter supports a specific protocol or technology.

Adapter Types:

Sender Adapters — receive messages INTO the integration flow:
- The sender system pushes messages to CPI, or CPI polls the sender system
- Configured on the left side (sender channel) of the iFlow

Receiver Adapters — send messages OUT from the integration flow:
- CPI sends the processed message to the target system
- Configured on the right side (receiver channel) of the iFlow

Commonly Used Adapters:

HTTP/HTTPS Adapter:
- Direction: Sender and Receiver
- Use: RESTful communication, generic HTTP calls
- Authentication: Basic, Client Certificate, OAuth 2.0
- Sender: exposes an HTTP endpoint on the CPI tenant
- Receiver: calls an external HTTP endpoint

SOAP Adapter:
- Direction: Sender and Receiver
- Use: SOAP web service communication
- Supports SOAP 1.1 and 1.2
- WS-Security support for message-level security
- WSDL-based configuration

OData Adapter:
- Direction: Sender and Receiver
- Use: OData V2 and V4 service communication
- Supports query operations ($filter, $select, $expand)
- Batch processing support
- Common for SAP S/4HANA and SuccessFactors integration

SFTP Adapter:
- Direction: Sender and Receiver
- Use: Secure file transfer
- Sender: polls an SFTP server for files
- Receiver: writes files to an SFTP server
- Supports key-based and password authentication
- File processing: delete, archive, or move after read

JDBC Adapter:
- Direction: Receiver only
- Use: Database operations (see detailed doc: 02-jdbc-adapter.txt)
- Supports multiple database vendors

RFC Adapter:
- Direction: Sender and Receiver
- Use: SAP RFC (Remote Function Call) communication
- Connects to SAP ECC/S4HANA via RFC protocol
- Requires SAP Cloud Connector for on-premise systems

IDoc Adapter:
- Direction: Sender and Receiver
- Use: SAP IDoc (Intermediate Document) exchange
- Native SAP document format for master data and transactions
- Often used for ECC integration

AMQP Adapter:
- Direction: Sender and Receiver
- Use: Message queue communication (Advanced Message Queuing Protocol)
- Supports MSA-based message queuing
- Used with SAP Event Mesh, RabbitMQ, Azure Service Bus

Kafka Adapter:
- Direction: Sender and Receiver
- Use: Apache Kafka event streaming
- Supports consumer groups and topic subscriptions
- Used for event-driven integration patterns

Mail Adapter:
- Direction: Sender and Receiver
- Use: Email communication (IMAP/POP3 for receiving, SMTP for sending)
- Supports attachments
- Often used for notifications and alerts

AS2 Adapter:
- Direction: Sender and Receiver
- Use: B2B communication using AS2 protocol
- MDN (Message Disposition Notification) support
- Certificate-based security
- See detailed B2B docs for more

JMS Adapter:
- Direction: Sender and Receiver
- Use: Internal CPI message queuing
- Used for asynchronous decoupling within CPI
- Provides retry and persistence capabilities
- Each tenant has a limited number of JMS queues

ProcessDirect Adapter:
- Direction: Sender and Receiver
- Use: Connects two integration flows within the same tenant
- Synchronous communication between iFlows
- No network overhead — in-process communication

SuccessFactors Adapter:
- Direction: Sender and Receiver
- Use: SAP SuccessFactors OData API
- Supports compound employee API
- Specific operations for SF entities

Adapter Security:

Authentication methods vary by adapter but generally include:
- Basic Authentication (user/password)
- Client Certificate Authentication
- OAuth 2.0 (Client Credentials, Authorization Code)
- Principal Propagation (SSO through SAP Cloud Connector)
- API Key

Security Material:
- Credentials are stored in the Security Material section of CPI
- User Credentials: username/password pairs
- Secure Parameter: encrypted key-value pairs
- Keystore: certificates and keys
- Known Hosts: SSH host keys for SFTP
- OAuth2 Credentials: OAuth configuration

Cloud Connector:
For on-premise system connectivity, SAP Cloud Connector provides a secure tunnel:
- Installed in the on-premise network
- Creates a reverse-invoke connection to SAP BTP (no inbound firewall rules needed)
- Maps virtual hosts to on-premise systems
- Supports HTTP, RFC, LDAP, and Mail protocols

Best Practices for Adapter Configuration:
1. Use the most specific adapter available (e.g., OData adapter for OData services instead of generic HTTP).
2. Always use encrypted communication (HTTPS, SFTP instead of FTP).
3. Store credentials in Security Material — never hardcode in scripts.
4. Configure appropriate timeouts to prevent hanging connections.
5. Use connection pooling where available for better performance.
6. Test adapter connectivity independently before building complex flows.
7. Document adapter configurations and the systems they connect to.
