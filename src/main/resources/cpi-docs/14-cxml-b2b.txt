cXML (Commerce XML) in SAP CPI B2B
Source: SAP Help Portal - cXML Processing, Ariba Network Integration

cXML (Commerce eXtensible Markup Language) is an XML-based standard designed for B2B procurement and supply chain communication. It is the native protocol of the SAP Ariba Network and is widely used in procurement scenarios.

What is cXML:
cXML defines a set of XML document types for business-to-business transactions. Unlike EDI (EDIFACT/X12), cXML is human-readable XML and does not require specialized parsers or converters. It uses HTTP/HTTPS as the transport protocol.

Key cXML Document Types:

Procurement:
- PunchOutSetupRequest/Response: Initiates a PunchOut session from a buyer's procurement system to a supplier's catalog
- PunchOutOrderMessage: Contains items selected during a PunchOut session, sent back to the buyer
- OrderRequest: Purchase order sent from buyer to supplier
- ConfirmationRequest: Order confirmation from supplier to buyer
- ShipNoticeRequest: Advance shipping notification from supplier
- InvoiceDetailRequest: Invoice from supplier to buyer

Catalog:
- CatalogUploadRequest: Upload product catalog data
- Subscription: Subscribe to catalog updates

Payment:
- PaymentRemittanceRequest: Payment notification
- PaymentProposalRequest: Payment proposal

cXML Message Structure:

Every cXML document follows this structure:
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE cXML SYSTEM "http://xml.cxml.org/schemas/cXML/1.2.050/cXML.dtd">
<cXML version="1.2.050" payloadID="unique-id" timestamp="2023-01-15T12:00:00+00:00">
  <Header>
    <From>
      <Credential domain="NetworkID">
        <Identity>sender-id</Identity>
      </Credential>
    </From>
    <To>
      <Credential domain="NetworkID">
        <Identity>receiver-id</Identity>
      </Credential>
    </To>
    <Sender>
      <Credential domain="NetworkID">
        <Identity>sender-id</Identity>
        <SharedSecret>shared-secret-token</SharedSecret>
      </Credential>
      <UserAgent>Procurement System 1.0</UserAgent>
    </Sender>
  </Header>
  <Request>
    <!-- Document-specific content here -->
  </Request>
</cXML>

cXML Response:
Every cXML request receives a synchronous response:
<cXML>
  <Response>
    <Status code="200" text="OK">Success</Status>
  </Response>
</cXML>

Status codes follow HTTP conventions: 200 (OK), 400 (Bad Request), 401 (Unauthorized), 500 (Internal Server Error).

PunchOut Flow (Most Common cXML Scenario):

1. Buyer opens procurement catalog in their ERP/procurement system
2. ERP sends PunchOutSetupRequest to supplier via CPI
3. CPI routes to supplier's commerce platform
4. Supplier returns PunchOutSetupResponse with a URL to their catalog
5. Buyer browses supplier's catalog in a web browser
6. Buyer selects items and clicks "checkout"
7. Supplier sends PunchOutOrderMessage back to buyer's ERP via CPI
8. Items appear in buyer's shopping cart
9. Buyer approves and sends OrderRequest (purchase order) via CPI to supplier

Processing cXML in CPI:

Since cXML is standard XML, processing in CPI is straightforward:
- Parse with XPath in Content Modifiers
- Transform with Message Mapping or XSLT
- Validate against cXML DTD/XSD schemas
- No special converter needed (unlike EDI)

Example — Extracting Order Details from cXML OrderRequest:
import com.sap.gateway.ip.core.customdev.util.Message
import groovy.xml.XmlSlurper

def Message processData(Message message) {
    def body = message.getBody(String)
    def cxml = new XmlSlurper().parseText(body)

    def orderID = cxml.Request.OrderRequest.OrderRequestHeader.@orderID.text()
    def orderDate = cxml.Request.OrderRequest.OrderRequestHeader.@orderDate.text()
    def buyerName = cxml.Header.From.Credential.Identity.text()

    def items = cxml.Request.OrderRequest.ItemOut.collect { item ->
        [
            lineNumber: item.@lineNumber.text(),
            quantity: item.@quantity.text(),
            description: item.ItemDetail.Description.text(),
            unitPrice: item.ItemDetail.UnitPrice.Money.text()
        ]
    }

    message.setProperty("orderID", orderID)
    message.setProperty("orderDate", orderDate)
    message.setProperty("itemCount", items.size().toString())

    return message
}

cXML with SAP Ariba Network:

SAP Ariba Network is the world's largest B2B trading network. CPI integrates with Ariba using cXML.

Common Ariba Integration Scenarios via CPI:
1. Ariba -> CPI -> S/4HANA: Purchase orders from Ariba to SAP backend
2. S/4HANA -> CPI -> Ariba: Invoices, confirmations, ship notices to Ariba
3. Ariba PunchOut -> CPI -> Supplier: Catalog browsing via PunchOut
4. Ariba -> CPI -> Non-SAP: Route Ariba documents to non-SAP receivers

Ariba Network Configuration:
- Ariba Network ID (ANID): unique identifier on the Ariba Network
- Shared Secret: authentication token for cXML communication
- Endpoint URL: CPI endpoint registered in Ariba Network as the integration middleware
- Transaction rules: configured in Ariba to route documents through CPI

cXML vs EDI for B2B:

| Aspect | cXML | EDI (EDIFACT/X12) |
|--------|------|-------------------|
| Format | XML (human-readable) | Fixed-format (needs specialized tools) |
| Transport | HTTP/HTTPS | AS2, SFTP, VAN |
| Adoption | Procurement-focused | Broad industry use |
| Acknowledgment | Synchronous HTTP response | Separate acknowledgment message (997, CONTRL) |
| Processing | Standard XML tools | Requires EDI parser/converter |
| Schema | DTD/XSD based | EDI standard schemas |
| Typical use | Ariba, procurement | Retail, logistics, manufacturing |

Best Practices for cXML Processing:
1. Validate cXML against the official DTD/XSD before processing.
2. Always return a proper cXML Response with status code (even for errors).
3. Use the payloadID for duplicate detection and message tracking.
4. Store the SharedSecret securely in CPI Security Material.
5. Handle cXML version differences — partners may use different cXML versions.
6. Log cXML Header information (From, To, Sender) for audit trails.
7. Test PunchOut flows end-to-end — they involve browser redirects that can be tricky.
8. Monitor Ariba Network transaction status alongside CPI monitoring.
