AS2 Adapter for B2B Communication in SAP CPI
Source: SAP Help Portal - AS2 Adapter

AS2 (Applicability Statement 2) is the most widely used protocol for B2B document exchange. It provides secure, reliable, and verifiable message delivery over HTTP/HTTPS. AS2 is commonly used for EDI document exchange between trading partners.

How AS2 Works:
1. Sender signs and/or encrypts the message
2. Message is sent over HTTPS to the receiver's AS2 endpoint
3. Receiver decrypts and verifies the signature
4. Receiver processes the message
5. Receiver sends back an MDN (Message Disposition Notification) as acknowledgment

Key AS2 Concepts:

AS2 ID:
A unique identifier for each party in AS2 communication. Both sender and receiver have their own AS2 ID. These IDs are used to identify partners and look up certificates.

MDN (Message Disposition Notification):
An acknowledgment message sent by the receiver back to the sender confirming:
- Message was received
- Message was successfully decrypted
- Signature was verified
- Message was processed (or failed)

MDN Types:
- Synchronous MDN: Returned immediately in the HTTP response
- Asynchronous MDN: Returned later via a separate HTTP request to a callback URL

AS2 Sender Adapter Configuration:
The AS2 sender adapter exposes an endpoint on the CPI tenant to receive AS2 messages from partners.

Settings:
- Message ID: How the AS2-From and AS2-To headers are determined
- Partner AS2 ID: Sender's AS2 identifier
- Own AS2 ID: Your AS2 identifier
- Message Security:
  - Verify Signature: validate the sender's digital signature
  - Decrypt Message: decrypt the message using your private key
- MDN Configuration:
  - Send MDN: whether to return an acknowledgment
  - Sign MDN: whether to sign the MDN
  - MDN Type: Synchronous or Asynchronous

AS2 Receiver Adapter Configuration:
The AS2 receiver adapter sends AS2 messages to trading partners.

Settings:
- Recipient URL: Partner's AS2 endpoint URL
- Own AS2 ID: Your AS2 identifier
- Partner AS2 ID: Receiver's AS2 identifier
- Message Security:
  - Sign Message: sign with your private key
  - Encrypt Message: encrypt with partner's public certificate
  - Signing Algorithm: SHA-1, SHA-256, SHA-384, SHA-512
  - Encryption Algorithm: 3DES, AES-128, AES-192, AES-256
  - Compress Message: optional ZLIB compression
- MDN Configuration:
  - Request MDN: whether to request an acknowledgment
  - Request Signed MDN: whether the MDN should be signed
  - MDN Type: Synchronous or Asynchronous
  - Async MDN URL: callback URL for asynchronous MDN

Certificate Setup for AS2:

For Sending (Outbound):
1. Your private key + certificate: stored in CPI Keystore for signing
2. Partner's public certificate: stored in CPI Keystore for encryption

For Receiving (Inbound):
1. Your private key + certificate: stored in CPI Keystore for decryption
2. Partner's public certificate: stored in CPI Keystore for signature verification

Steps to set up certificates:
1. Exchange public certificates with your trading partner
2. Import partner's certificate into CPI Keystore (Operations -> Manage Security -> Keystore)
3. Ensure your own key pair is in the Keystore
4. Reference the correct aliases in adapter configuration

AS2 with Partner Directory:
For multi-partner scenarios, use the Partner Directory to store partner-specific AS2 configuration:
- AS2 partner IDs
- Certificate aliases per partner
- Endpoint URLs per partner
- MDN preferences per partner

This allows a single iFlow to handle multiple partners dynamically.

Common AS2 Scenarios:

Scenario 1: Receiving EDI Purchase Orders
Partner -> AS2 Sender Adapter -> CPI -> EDI-to-XML Converter -> Mapping -> IDoc Receiver -> SAP ECC

Scenario 2: Sending EDI Invoices
SAP ECC -> IDoc Sender -> CPI -> Mapping -> XML-to-EDI Converter -> AS2 Receiver Adapter -> Partner

Scenario 3: AS2 with Ariba Network
Ariba -> AS2/cXML -> CPI -> Transform -> S/4HANA

Troubleshooting AS2:
1. MDN Failures: Check certificate validity and algorithm compatibility
2. Decryption Errors: Ensure the correct private key alias is configured
3. Signature Verification Failures: Partner may have renewed their certificate — update it in Keystore
4. Connection Timeouts: Check network connectivity and firewall rules
5. Message Size Issues: Large attachments may need compression enabled

Best Practices:
1. Always use HTTPS (not HTTP) for AS2 communication.
2. Use SHA-256 or higher for signing — SHA-1 is deprecated.
3. Use AES-256 for encryption — avoid 3DES for new setups.
4. Request signed MDN to ensure non-repudiation.
5. Monitor certificate expiry dates and renew proactively.
6. Keep a record of all partner certificate exchanges.
7. Test AS2 connectivity with tools like Mendelson AS2 or Drummond before going live.
8. Use asynchronous MDN for large messages to avoid HTTP timeouts.
