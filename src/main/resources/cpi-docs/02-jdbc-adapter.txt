Configuring the JDBC Adapter in SAP CPI
Source: SAP Help Portal - JDBC Receiver Adapter

The JDBC (Java Database Connectivity) adapter allows integration flows to connect to databases. CPI supports only the JDBC Receiver adapter — it sends SQL statements to a database and retrieves results.

Prerequisites:
1. A JDBC data source must be configured on the tenant. This is done by the tenant administrator.
2. The database driver (JAR file) must be deployed to the tenant.
3. The data source name must be known and available in the adapter configuration dropdown.

Supported Databases:
- SAP HANA (cloud and on-premise)
- Microsoft SQL Server
- Oracle Database
- IBM DB2
- PostgreSQL
- MySQL / MariaDB
- SAP ASE (Sybase)

Configuration Steps:

Step 1: Deploy the JDBC Driver
- Go to Operations view in CPI web UI
- Navigate to Manage Security -> JDBC Material
- Upload the appropriate JDBC driver JAR for your database

Step 2: Configure the Data Source
- Go to Operations view
- Navigate to Manage Security -> JDBC Data Sources
- Create a new data source with:
  - Data Source Name: a logical name (e.g., "MY_HANA_DB")
  - Database Type: select the database vendor
  - JDBC URL: the connection string (e.g., jdbc:sap://host:port)
  - User and Password: database credentials

Step 3: Use the JDBC Adapter in an iFlow
- Add a receiver channel in your integration flow
- Select JDBC as the adapter type
- Configure the adapter:
  - Data Source: select the data source name configured in Step 2
  - SQL Statement: Choose between:
    a) Native SQL: Write the SQL directly in the adapter
    b) SQL from Message Body: The message body contains the XML-formatted SQL

Writing SQL Statements:
For native SQL, you write the SQL directly. For XML-based SQL, the message body must follow this format:

For SELECT:
<root>
  <Select>
    <entity>TABLE_NAME</entity>
    <selectAttribute>COLUMN1, COLUMN2</selectAttribute>
    <whereCondition>COLUMN1 = 'value'</whereCondition>
  </Select>
</root>

For INSERT:
<root>
  <Insert_Statement>
    <dbTableName action="INSERT">
      <table>TABLE_NAME</table>
      <access>
        <COLUMN1>value1</COLUMN1>
        <COLUMN2>value2</COLUMN2>
      </access>
    </dbTableName>
  </Insert_Statement>
</root>

For UPDATE:
<root>
  <Update_Statement>
    <dbTableName action="UPDATE">
      <table>TABLE_NAME</table>
      <access>
        <COLUMN1>new_value</COLUMN1>
      </access>
      <key>
        <ID>123</ID>
      </key>
    </dbTableName>
  </Update_Statement>
</root>

For DELETE:
<root>
  <Delete_Statement>
    <dbTableName action="DELETE">
      <table>TABLE_NAME</table>
      <key>
        <ID>123</ID>
      </key>
    </dbTableName>
  </Delete_Statement>
</root>

Batch Processing:
The JDBC adapter supports batch operations. You can include multiple INSERT or UPDATE statements in a single XML payload using multiple <access> elements. This improves performance for bulk operations.

Error Handling with JDBC:
- If the SQL statement fails, the adapter throws an exception that can be caught by the iFlow error handling.
- Common errors: connection timeout, authentication failure, SQL syntax errors, constraint violations.
- Use the "On Error" setting in the adapter to control behavior: Stop Processing or Continue Processing.

Best Practices:
1. Always use parameterized queries when possible to prevent SQL injection.
2. Configure connection pool settings appropriately — too many open connections can overwhelm the database.
3. Use transactions when performing multiple related database operations.
4. Test SQL statements directly against the database before configuring them in CPI.
5. Monitor data source connectivity regularly in the Operations view.
6. Use the JDBC adapter's built-in retry mechanism for transient connection failures.
